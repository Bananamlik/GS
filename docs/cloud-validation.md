# v34-runtime-6 클라우드 검증

후속 변경과 현재 결과: [v34-runtime-8](cloud-runtime-8.md). 이 문서는 runtime-6의 기록이다.

## 구현

- 전투 준비 전 유휴 RAF에서 FPS 목표를 고정하고, 요청한 30/60FPS보다
  낮아지지 않게 했다. 단계별 시간과 느린 작업 스택을 기록한다.
- VFX 예열을 직렬화하고 실제 시전·화면 전환·컨텍스트 손실에 따른 취소와
  소유권 반환을 처리한다. 렌더 타깃은 비동기 대기 전에 복원한다.
- 병렬 셰이더 컴파일을 지원하지 않는 환경에서는 선택된 전투 효과를 시작 전에
  준비한다. 예열 렌더는 효과와 필요한 조명으로 제한한다.
- 출력이 LinearSRGB / NoToneMapping일 때 마지막 복사 패스를 생략한다.
  색 변환이 필요한 설정은 기존 OutputPass를 사용한다.
- CH:storm의 투명도 0 표면을 생략하고, 원뿔 파편을 투명 표면 사이의 깊이
  구간별로 묶었다. 원래 모델뷰 행렬·색·투명도와 양면 렌더를 유지하며, 같은
  깊이의 정렬은 원래 개별 물체로 처리한다. 다른 네이티브 효과는 그대로다.
- WebGL 복구 후 계속하기는 현재 장면과 전투 효과의 재준비를 기다린다.
  손실 중 재개를 막고, 복구 준비 실패 시 일시정지 상태에서 재시도한다.
  복구 중 다시 손실되면 대기를 취소하며, 컴파일 대기는 15초로 제한한다.
  체크포인트 재개 안내도 실제 예열 완료 여부를 확인한다.

## 검증 범위

검사는 현재 로컬 실행본을 대상으로 한다. 첨부 v34 보고서의 과거 검사·병합
기록은 이번 수행 실적으로 합산하지 않았다.

- 두 HTML 동일성 및 모든 실행 스크립트 문법 검사.
- FPS 목표/측정 실패/설정 변경, 비동기 예열 직렬화·취소·소유권·렌더 타깃
  복원·컴파일 실패·병렬 확장 미지원 경로.
- OutputPass 색 변환 및 실제 픽셀 비교.
- CH:storm: 카메라 3방향 × 시간 5개, 일반 알파 표면이 끼어드는 조건에서
  원래 렌더와 채널 차이 최대 1/255 이내, 호출 감소 확인.
- 스킬 425개 / 변형 767개의 사양·VFX 등록 및 고정 시드 6초 판정 재현성.
  CSV 767행의 ID·크기·형태·피해·준비·판정·사거리도 대조한다.
  전체 변형의 실제 VFX 영상/음향 승인을 의미하지 않는다.
- 기존 CC 규칙, 대표 실제 시전 4건의 피해·CC·VFX 전달.
- 320/390/1280px 라이브러리·상세·검토 패널, 체크포인트 재개와 실제
  WEBGL_lose_context 손실·복구, 장비 변경, 보상 선택의 다음 웨이브 체크포인트 반영과 LAB 장비 복원,
  실제 터치 시전·속박 중 입력 제한·일시정지, 반복/A·B/취소/JSON 저장 흐름.
- 실제 RAF의 단기 성능 및 10분 6웨이브 반복·GPU 자원 표본.

## 성능 해석

Cloud Chromium 151 / SwiftShader, 390×844, 터치, FPS 제한 60,
준비 후 워밍업 5초와 전투 측정 60초 조건의 CPU 프로파일 검사:

| 항목 | 이전 runtime-5 | 구간 묶음 runtime-6 |
| --- | ---: | ---: |
| 평균 FPS | 15.0 | 14.9 |
| 최대 렌더 호출 | 496 | 222 |
| 최대 프레임 ms | 559.2 | 647.9 |
| 시작 준비 초 | 9.65 | 9.80 |

호출 비용 감소는 확인했지만 이 환경의 FPS 개선과 프레임 예산 충족은 확인하지
못했다. GPU 처리와 셰이더 링크 대기가 여전히 크다. 첫 준비 비용을 전투 중으로
옮겨서 대기시간 감소로 보고하지 않는다. 위 프로파일은 복구 안내 수정 직전의
runtime-6 측정이며, 최종 전체 회귀와 장시간 측정 결과는 작업 결과 기록에 남긴다.

## 10분 반복 결과

실제 RAF 600초, 워밍업 5초, 60FPS 제한에서 6웨이브를 3회 완주했다.
예열 실패 0건, 페이지 오류 0건. 평균 12.3FPS, p95 238.1ms, p99 409.9ms,
최대 1878.6ms로 프레임 예산은 충족하지 못했다. 초반 60초는 12.6FPS, 후반
60초는 12.5FPS였다. 이 실행만으로 짧은 측정과의 성능 차이 원인을 확정하지 않는다.

GPU 지오메트리 최대 428개·텍스처 최대 21개. 마지막 지오메트리 278개·텍스처
13개로 회수됐다. 초기 이후 장면 루트 202개, 파편 묶음 최대 58개를 유지했다.
관찰 범위에서 지속적인 GPU 자원 증가는 확인하지 않았으며 JS 힙 전체의 누수
부재를 증명한 검사는 아니다.

측정 소스 SHA256: `afaf0923ce6c444e3808636953a833800c7828482ccf28bec26699ef5fd32f24`.
이 측정 뒤 복구 중 재손실의 대기 취소·시간 제한을 추가했다. 전투 렌더와 판정
코드는 이 추가 수정에서 바꾸지 않았으며, 복구 수정은 최종 회귀 검사로 검증한다.

최종 실행본 SHA256: `50a474c2730c0469faeba8759510ae5d263a3ca3b1721fd47e76792d17fd3fa7`.
GA_SIM과 GA_SKILLS의 전체 스크립트는 초기 main과 동일하다.
