## 2. 구조 계층

| 계층 | 단위 | 수명 | 담는 것 |
|---|---|---|---|
| 계정 (Meta) | 1개 | 영구 (localStorage) | 해금 목록, 영구 화폐, 최고 기록, 난이도 단계, 설정 |
| 런 (Run) | 한 번의 도전 | 시작 → 사망/승리 | 영웅, 장착 스킬 6칸, 패시브 목록, 골드, 체력, 현재 지역·노드, 런 시드 |
| 지역 (Act) | 3개 | 런 안 | 노드 지도, 적 구성 표, 지역 보스, 경기장 배치 |
| 노드 (Node) | 지역당 5~7개 | 지역 안 | 종류(전투·정예·상점·이벤트·휴식·보스), 보상 |
| 전투 (Encounter) | 노드 1개 | 수십 초~2분 | 웨이브 1~3개. **현재 `GA_SIM` 1회 실행과 같음** |

핵심 결정: **전투 1개 = 기존 `GA_SIM.create(data, heroKey, seed)` 1회**. 노드마다 `data.waves`를 짧게 만들어 넘긴다. 전투 코어는 거의 그대로 쓰고, 위에 런·맵 계층만 새로 얹는다.

## 3. 화면 흐름 (상태 기계)

```
타이틀 ─▶ 영웅 선택 ─▶ 지역 지도 ─┬▶ 전투/정예 ─▶ 보상(드래프트·골드) ─┐
   ▲                           ├▶ 상점 ─────────────────────────────┤
   │                           ├▶ 이벤트(선택지) ────────────────────┤
   │                           ├▶ 휴식(회복 or 강화) ─────────────────┤
   │                           └▶ 지역 보스 ─▶ 보상 ─▶ 다음 지역 지도 ─┘
   │                                              (3지역 보스 처치 = 승리)
   └──── 런 결과(승리/사망) ─▶ 영구 보상 정산 ─▶ 해금 화면 ◀─────────────
```

| 상태 | 화면 | 기존 요소 재사용 |
|---|---|---|
| `title` | 시작, 이어하기, 해금, 설정 | `#gaMenu` (현재 `data-mode="select"`/`"pause"`) |
| `heroSelect` | 영웅 4명 + 잠김 표시 | `#gaHeroes`, `#gaHeroInfo` |
| `map` | 지역 노드 지도 (갈림길 2~3개) | 신규 (DOM 오버레이) |
| `encounter` | 전투 | 기존 게임 화면 전체 |
| `reward` | 스킬 드래프트, 골드, 패시브 | `openDraft` / `#gaDraftCards` |
| `shop` | 스킬·패시브·회복 구매 | 신규, 카드 UI는 드래프트 재사용 |
| `event` | 글 + 선택지 2~3개 | 신규 |
| `rest` | 체력 회복 or 스킬 크기 강화 | 신규 (작음) |
| `runEnd` | 결과, 통계, 영구 보상 | `#gaResult`, `resultDetails()` |
| `meta` | 해금 트리 | 신규 |

## 4. 런 상태 데이터 (초안)

```js
run = {
  schema: 1, contract: 'gs-run-1',
  seed, heroKey, difficulty: 0,         // 난이도 단계 (메타에서 해금)
  act: 1, nodeId: 'a1-n3',              // 현재 위치
  map: { a1: [{id, kind, next:[...], cleared}], a2: [...], a3: [...] },
  hero: { hp, hpMax },                  // 전투 사이 유지
  kit: [skillRef x6],                   // {id, size} — GA_SKILL_LIB 참조
  passives: [{id, stacks}],
  gold: 0,
  stats: { kills, damage, taken, nodes, time },
  history: [{nodeId, kind, result}]
}
meta = {
  schema: 1, contract: 'gs-meta-1',
  shards: 0,                            // 영구 화폐
  unlocked: { heroes:['bolt','rain'], skillPool:[...], traits:[...] },
  best: { bolt:{act, time}, ... }, maxDifficulty: 0
}
```

- 저장 시점: 노드 시작 직전(런), 런 종료 시(메타). 전투 중간 저장은 없음.
- 기존 `gs-wave-boundary-1`은 전투 안 웨이브 경계용으로 남긴다. 런 저장은 별도 키(`gs-run-1`).
- 검증 함수는 기존 `validSave` 방식(스키마·범위·유한수 검사)을 그대로 따른다.

## 5. 노드 종류

| 종류 | 비율(초안) | 내용 | 보상 |
|---|---|---|---|
| 전투 | 45% | 웨이브 1~2개, 일반 적 | 골드 + 드래프트(스킬 3택 1) |
| 정예 | 15% | 웨이브 1개, 엘리트 1~2 + 호위 | 골드 많이 + 패시브 3택 1 |
| 상점 | 10% | 스킬 2, 패시브 2, 회복 1 | 골드 소비 |
| 이벤트 | 15% | 위험/보상 선택지 | 다양 (체력↔골드, 저주↔강화) |
| 휴식 | 10% | 체력 30% 회복 or 스킬 크기 1단계 업 | — |
| 보스 | 지역 끝 1개 | 지역 보스 | 대량 골드 + 궁극기 드래프트 + 영구 화폐 |

지도 생성: 런 시드로 결정적. 층 5~7개, 층마다 노드 2~3개, 다음 층으로 1~2개 연결. 마지막 층은 보스 하나.

## 6. 성장 축

| 축 | 런 안 / 밖 | 기존 코드 | 새로 필요한 것 |
|---|---|---|---|
| 스킬 교체 | 안 | `draftOffers`, `GA_DRAFT_POLICY` (역할·연계 추천) | 평점 3 이상 필터, 노드 등급별 후보 |
| 스킬 크기 업 | 안 | 라이브러리 변형 S/M/L/XL | 휴식·상점에서 한 단계 올리기 |
| 패시브 | 안 | 없음 | 패시브 표 (예: 피해 +10%, 쿨 -8%, 상태 지속 +1초, 노출 증폭 +10%, 처치 시 실드). 전투 시작 시 `kit` 사본에 적용 |
| 골드 | 안 | 없음 | 전투 보상·상점 |
| 영구 화폐 | 밖 | 없음 | 런 결과로 정산 (도달 지역·처치·보스) |
| 해금 | 밖 | 영웅 4명, 스킬 425 | 영웅 2명 + 스킬 풀 일부로 시작, 나머지 해금 |
| 난이도 단계 | 밖 | 없음 | 승리 시 다음 단계 열림. 단계마다 적 체력·피해 +15% 등 |

패시브는 **전투 코어 밖에서** 스킬 사본 값을 바꾸는 방식으로 넣는다(예: `damage*1.1`, `cd*0.92`). `GA_SIM` 내부 규칙은 건드리지 않는다. 결정성 유지.

## 7. 지역 콘텐츠 (초기안, 기존 자산만 사용)

| 지역 | 분위기 | 적 구성 | 지역 보스 | 경기장 |
|---|---|---|---|---|
| 1 | 해안 폐허 (현재) | 잡귀, 원귀궁 | 엘리트 잡귀 강화형 (체력 ×3, 보스 페이즈 규칙 차용) | 기둥 8개 (현재) |
| 2 | 저주받은 숲 | 역귀, 술사, 잡귀 | 술사 강화형 (`GA_ENEMY_LIB.mage` 다중 시전) | 기둥 배치 변경 (`setSolids`) |
| 3 | 심연 | 전 종류 혼합 + 엘리트 | 두억시니 (현재 보스) | 기둥 축소, 장판 위험 |

- 적 6종·보스 1종만 있어 지역 차이는 구성·배치·배율로 먼저 만든다. 새 적·보스 디자인은 뼈대 이후.
- 지역 배율(초안): 체력 ×1 / ×1.6 / ×2.4, 피해 ×1 / ×1.3 / ×1.6.
