# GS Action 거점 방어 계획 v1

상태: **초안. 소유자 승인 전.** 승인되면 `gs-game-pillars_v1`의 §1(플레이 방식)·§3(목표)과 `gs-combat-design_v1`의 D1·D2·D3(플랫폼·조준·카메라)을 이 문서가 대체한다.

소유자가 정한 것 (2026-10-10):
- 적 = 탱크·차량·드론·함선 등 기계. 퇴치하는 게임.
- 전진형보다 지키는 디펜스류. 드로우콜을 고려한다.
- 적 모델은 GS-G1에 이미 구현된 절차적 모델링(Forge)을 쓴다.
- 굿·넋 세계관은 쓰지 않는다.

아래 A1~A8은 제안이다. 각 항목에 대안을 적었다.

## 1. 한 줄

**해안 도시의 거점을, 몰려오는 기계 무리로부터 스킬로 지킨다.**

## 2. 제안

| # | 항목 | 제안 | 이유 | 대안 |
|---|---|---|---|---|
| A1 | 방식 | 영웅 1명이 직접 뛰는 거점 방어. 타워 건설 메뉴 없음. 설치물 스킬(43개)이 포탑 역할 | 조작 재미 유지. 새 UI·경제 불필요 | 타워 배치 중심(영웅 없음) / 혼합(건설 자원 추가) |
| A2 | 지키는 것 | 거점 1개(체력 있음). 후반 구역에서만 2개 | 화면 하나에 다 보임. 모바일에서 판단이 단순 | 처음부터 여러 개 |
| A3 | 패배 | 거점 체력 0 = 런 종료. 영웅이 쓰러지면 5초 뒤 거점 옆에서 부활(그동안 무방비) | "지키는 게임"의 긴장이 거점에 모임. 한 번의 실수로 판이 끝나지 않음 | 영웅 사망도 런 종료(현행) |
| A4 | 시점 | 고정 카메라, 위에서 비스듬히(약 55°). 화면 중심 = 거점과 영웅 사이. 시점 조작 없음 | 모바일 엄지 2개로 충분. 바닥형 스킬·적 예고가 가장 잘 보임 | 현행 3인칭 유지 |
| A5 | 조준 | 버튼 탭 = 가장 위협적인 적(거점에 가장 가까운 적)에게 자동. 버튼 누른 채 드래그 = 직접 지정. PC는 마우스 지점 | 터치에서 조준 부담 제거. 직접 지정으로 판단 여지 유지 | 전부 수동 |
| A6 | 공중·해상 | 판정은 평면 그대로. 드론은 "공중" 표시만 달고 높이 띄워 그림(1차: 모든 스킬이 맞음). 함선은 구역 밖 바다에 떠 있는 포대, 구역 보스 | 전투 코어(`GA_SIM`) 변경 최소 | 공중 전용 판정 추가(스킬 243개 재분류 필요) |
| A7 | 한 판 | 구역 4개 × 웨이브 4 + 마지막 함선전. 12~15분. 웨이브 사이 스킬 선택, 구역 사이 지도·상점(현행 런 구조) | 모바일 한 판 길이. 기존 런·보상 코드 재사용 | 끝없는 웨이브(점수 경쟁) |
| A8 | 설정 | 한 줄만: "무인 기계 군단이 해안 도시로 들어온다. 방어선은 능력자 한 명." 인물·대사 없음 | 세계관 불필요 방침. 스킬이 초능력인 이유만 남김 | 설정 없음 |

## 3. 적

기존 적 6종의 행동을 그대로 쓰고 이름·모델·수치만 바꾼다(1차). 새 행동은 2차.

| 새 적 | 기존 행동 | 하는 일 | 플레이어가 할 일 | G1 모델 출처(확인 필요) |
|---|---|---|---|---|
| 소형 드론 | 잡귀(돌격) | 다수가 거점으로 직행 | 광역으로 쓸어담기 | 미확인 |
| 장갑차 | 원귀궁(직선 사격) | 멀리서 직선 예고 후 사격 | 옆걸음, 접근해 처치 | `forges/cars.js` 또는 `tank.js` |
| 전차 | 엘리트(강한 돌격) | 느리고 단단함. 거점 포격 | 틈에 큰 스킬 | `forges/tank.js` |
| 자주포 | 술사(예고 원) | 뒤에서 예고 원 낙탄 | 원 밖으로, 우선 처치 | `forges/tank.js` |
| 지뢰 살포차 | 역귀(장판) | 바닥을 막음 | 이동 경로 선택 | `forges/cars.js` |
| 함선 | 두억시니(보스) | 바다에서 포격 3단계 | 패턴 읽기, 포탑부터 | `forges/ship.js` |

새로 필요한 규칙은 하나: **적의 목표 선택**. 지금은 전부 영웅을 쫓는다. 거점을 노리는 적과 영웅을 노리는 적을 적 종류별 값으로 나눈다.

## 6. 단계 (각 단계 = 코드 PR 1개, 테스트 포함)

| 단계 | 내용 | 건드리는 곳 | 완료 기준 |
|---|---|---|---|
| F1 | 거점: 체력, 피격, 패배 조건. 적 목표 선택(거점/영웅) | `GA_SIM`, `GA_DATA` | Node 테스트: 방치하면 거점 파괴로 패배, 같은 시드 2회 동일 |
| F2 | 진입로: 웨이브가 지정한 방향 2~3곳에서 등장. 영웅 부활 | `GA_SIM`, `GA_RUN` | 방향별 등장 수 테스트 |
| F3 | 고정 시점 + 자동 조준·드래그 지정 | 뷰, 입력 | 390×844와 844×390에서 조작 요소가 겹치지 않음. 탭 = 최우선 적 |
| F4 | 적 이름·수치 교체(§3), 임시 모델(상자) | `GA_DATA`, 뷰 | 6종이 구분되어 보임 |
| F5 | 한 판 구성(A7): 구역 4 + 함선전, 난이도 곡선 | `GA_RUN` | 자동 플레이로 완주 가능, 방치하면 2구역 안에 패배 |
| F6 | Forge 모델 반입 + 병합 메시 | 신규 블록 | 적 draw ≤ 100 측정값 |
| F7 | G1 구역을 배경으로 | G1 개선(W0~W5) 이후 | 별도 계획 |

F1~F5는 지금 저장소만으로 가능하다. F6부터 G1 파일이 필요하다.

## 7. 위험

- **수동성**: 가만히 서서 버튼만 누르는 게임이 될 수 있다. 대책 = 방향이 번갈아 열림, 자주포처럼 "가서 잡아야 하는" 적, 설치물로 한쪽을 잠시 맡김.
- **크기**: 사람 영웅과 전차의 크기 차. 스킬 반경·피해를 차량 기준으로 다시 잡아야 한다(F4·F5에서).
- **파일 크기**: Forge 반입 시 `tank.js` 104 KB, `ship.js` 145 KB, `cars.js` 316 KB. 필요한 종류만 고른다.
- **three.js 버전**: GS Action `0.186.0`, G1 `0.185.1`. Forge가 버전에 민감한지 UNVERIFIED.
- **재미**: 사람이 해 봐야 안다. F1~F4 뒤에 시험판으로 확인한다.
