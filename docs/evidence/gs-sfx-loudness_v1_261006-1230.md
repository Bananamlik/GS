# SFX 음량 측정 (Lab 미리보기, 효과 501개)

기록: 2026-10-06 12:30 KST. 환경: GitHub 러너 headless Chromium, SwiftShader. 효과마다 1회, 5.5초 재생. 측정 코드와 실행: 브랜치 `claude/probe-sfx` (`scripts/measure_sfx.py`, `.github/workflows/sfx-measure.yml`, 6개 shard). 원자료: `gs-sfx-loudness-raw_v1_261006-1230.json`.

## 방법과 한계

- `AudioNode.connect`로 스피커(destination) 연결을 가로채 블록(2048샘플)별 최대값과 파워를 기록했다. 모든 AudioContext(엔진마다 따로 생성됨)를 한 측정기로 합쳤다.
- 순간 음량(momentary)은 가중치 없는 RMS를 400ms 창으로 이동하며 구한 최댓값이다. LUFS 같은 보정된 값이 아니며 K-가중치, 장비 특성은 반영하지 않았다.
- 마스터 볼륨 이후 단계의 디지털 값이다(dBFS). 실제 체감은 기기 스피커와 이어폰에 따라 다르다.
- Lab 미리보기 1회 재생 기준이다. 실제 전투에서 여러 소리가 겹친 합산 음량은 측정하지 않았다.
- 소프트웨어 렌더링이라 프레임이 느리다. 프레임 루프에 의존하는 효과는 소리가 늦게 시작해 5.5초 안에 일부만 담겼을 수 있다. 짧은 소리(`D:PROJ:` 등, 활성 블록 중앙값 28/128)는 400ms 창에 무음이 섞여 있다. 개별 값은 오차가 있을 수 있고 분포의 경향을 보는 자료로 쓴다.
- 오류 0건. 소리가 측정되지 않은 효과 2개: `D:ULT:whale`, `C:F_PROJ:nbl` (실제 무음인지, 5.5초 안에 시작하지 않은 것인지는 확인하지 못함).

## 코드 구조 (원인 후보)

- 사운드 엔진이 여러 개이고(CHROMA, PORT, GS_AUDIO 등) 엔진마다 AudioContext와 마스터 볼륨(0.72, 0.65, 0.7)이 따로다.
- 엔진마다 압축기가 따로 있고, 효과 20종에만 음색·리미터 보정표(`window.__SFX_TAME`)가 있다. 나머지는 음량 정규화가 없다.
- 사용자 조절은 SFX 음소거 토글뿐이고 볼륨 슬라이더가 없다.

## 제안 (구현 전)

1. 효과별 보정 게인: 목표 = 중앙값(-24.6 dB 순간 음량), 보정 ±12 dB로 제한, 피크가 -3 dBFS를 넘지 않게 제한. 시뮬레이션 결과 p5~p95 폭이 26.1에서 6.1 dB로, 499개 중 473개가 목표 ±6 dB 안에 들어온다. 제한(±12 dB)에 걸리는 효과는 68개(주로 매우 조용한 `D:`, `SC-`)로 이 효과들은 목표까지 못 올라가며, 별도 확인이 필요하다. 보정표 초안: `gs-sfx-gain-proposal_v1_261006-1230.csv`.
2. 엔진 공통 SFX 볼륨 슬라이더(세 엔진의 마스터 게인에 곱함, 설정에 저장).
3. 피크 보호: 마스터 앞단에 리미터.
4. 적용 방식: 효과 id → 게인 표를 `__SFX_TAME`과 같은 자리에서 읽어 효과의 출력 앞에 게인 노드를 추가. 효과 소스는 수정하지 않는다.
5. 승인 전 확인: 보정 후 같은 측정을 다시 돌려 폭이 줄었는지 확인. 실제 기기에서 청취 확인(UNVERIFIED).
